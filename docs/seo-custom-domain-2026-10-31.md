# بررسی و اصلاح SEO دامنهٔ اصلی — ۳۱ اکتبر ۲۰۲۶

دامنهٔ اصلی این کسب‌وکار `https://doctorreson.ir` است. انتشار آن از GitHub به Worker با نام `doctor-resoon1` انجام می‌شود. سایت مدیریت‌شدهٔ قبلی در `doctor-resoon.cometolive34.chatgpt.site` هویت و دیتابیس مستقلی دارد.

## ایراد تأییدشده پیش از اصلاح

هر ۱۰ صفحهٔ دامنهٔ اصلی پاسخ ۲۰۰ می‌دادند، اما canonical، اطلاعات Open Graph، شناسه‌های JSON-LD، نقشهٔ سایت و نشانی sitemap در robots.txt به دامنهٔ قبلی اشاره می‌کردند. بنابراین وجود محتوا و حتی امتیاز ۱۰۰ SEO در Lighthouse به معنی درست بودن انتخاب دامنهٔ اصلی نبود. درخواست HTTP نیز به HTTPS منتقل نمی‌شد. `www.doctorreson.ir` در DNS پاسخ NXDOMAIN داشت.

## اصلاحات این نسخه

- `lib/site-origin.ts` مرجع ثابت دامنهٔ اصلی است. همهٔ صفحه‌ها، داده‌های ساختاریافته، تصویر اشتراک‌گذاری و نقشهٔ سایت از همین مرجع استفاده می‌کنند. هویت سایت از Host ورودی ساخته نمی‌شود.
- صفحه‌های دامنهٔ قبلی با ۳۰۱ به همان مسیر در دامنهٔ اصلی منتقل می‌شوند؛ query string حفظ می‌شود. HTTP و www نیز در صورت رسیدن درخواست به همین Worker، به HTTPS بدون www منتقل می‌شوند. اسلش انتهایی صفحه‌ها یکسان می‌شود و حلقهٔ انتقال ایجاد نمی‌شود.
- فایل تأیید گوگل، robots.txt، sitemap.xml، API و منابع ایستا از انتقال صفحه‌ها مستثنا هستند تا تأیید مالکیت قبلی و کلاینت‌های فعال قطع نشوند. فایل تأیید گوگل همان محتوای دقیق را با هدر `X-Robots-Tag: noindex` تحویل می‌دهد.
- پرترهٔ اصلی نسخه‌های واقعی AVIF با عرض ۳۲۰، ۴۸۰، ۷۶۸ و ۱۰۲۴ پیکسل دارد؛ حدود ۶، ۱۰، ۱۸ و ۲۵ کیلوبایت. WebP قبلی برای مرورگرهای فاقد پشتیبانی حفظ شده است. preload و `picture` از مجموعه و اندازه‌های یکسان استفاده می‌کنند؛ در بررسی مرورگر فقط یک درخواست پرتره ثبت شد.
- نام دسترس‌پذیر نشان برند با متن قابل مشاهده هماهنگ شد. بخش اعلان، دکمه‌های ثابت موبایل و راه‌های ارتباطی نام‌های معنایی متمایز دارند.
- هدرهای `nosniff` و Referrer-Policy اضافه شدند. HSTS فقط برای HTTPS دامنهٔ اصلی و بدون `includeSubDomains` اعمال می‌شود.
- اسکریپت فقط‌خواندنی `scripts/audit-seo.py` برای تکرار بررسی محلی یا دامنهٔ منتشرشده اضافه شد؛ این اسکریپت هیچ فرم یا رکوردی ثبت نمی‌کند.

## موارد موجود که دوباره بررسی شدند

۱۰ صفحهٔ عمومی شامل خانه، فهرست خدمات، چهار خدمت فعال، درباره، تماس، حریم خصوصی و کالری‌شمار هستند. هرکدام عنوان و توضیح یکتا، یک H1، canonical مستقل و محتوای کامل قابل خواندن بدون اجرای JavaScript دارند. پیوندهای داخلی، مسیر راهنما و ارجاع‌های JSON-LD بررسی شدند. صفحه‌های ناموجود ۴۰۴ و noindex برمی‌گردانند. APIها و پاسخ پیگیری noindex و no-store باقی مانده‌اند.

برنامهٔ تغذیه و ورزش، ویزیت آنلاین، مراقبت در منزل و واکسیناسیون فعال هستند. آزمایش و خدمات زیبایی در وضعیت «به‌زودی» می‌مانند. آدرس، محدودهٔ شهری، شمارهٔ نظام پزشکی، نظر بیمار، قیمت یا تخصص تأییدنشده به متن یا schema اضافه نشده است. اطلاعات کالری‌شمار، منبع USDA و محدودیت تخمین سهم مصرفی در صفحه قابل مشاهده‌اند.

## شواهد آزمون پیش از انتشار

- TypeScript، ساخت production و ۳۲ آزمون خودکار موفق شدند.
- خزش فقط‌خواندنی هر ۱۰ صفحه، یکتایی عنوان و توضیح، ۱۱ مقصد داخلی، ۲۸ پیوند دارای fragment، نقشهٔ سایت، robots، فایل تأیید و پاسخ‌های ۴۰۴ موفق بود.
- مرورگر در ۲۶ ترکیب صفحه/عرض نمایش از ۳۲۰ تا ۱۴۴۰ پیکسل بررسی شد؛ سرریز افقی و خطای JavaScript مشاهده نشد.
- بررسی axe برای صفحه‌های اصلی، درباره، تماس، کالری‌شمار و انتخاب خدمت در فرم، بدون نقض معیارهای A/AA و best-practice انجام شد.
- در D1 محلی جداگانه، ثبت درخواست ۲۰۱ و پیگیری ۲۰۰ بود. لینک واتساپ شمارهٔ درست و کد پیگیری را داشت. هیچ درخواست آزمایشی روی پایگاه دادهٔ واقعی ایجاد نشد.
- ثبت یک تخم‌مرغ آب‌پز در کالری‌شمار ۷۸ کیلوکالری نشان داد و پس از بارگذاری مجدد باقی ماند. انتخاب AVIF در DPRهای مختلف و fallback واقعی WebP نیز بررسی شد.
- Lighthouse موبایل پیش از تغییر روی دامنهٔ واقعی: عملکرد ۹۰، دسترس‌پذیری ۱۰۰، best practices ۱۰۰ و SEO ۱۰۰؛ LCP برابر ۳٫۲ ثانیه، CLS برابر ۰٫۰۰۲. این یک آزمون آزمایشگاهی است و نتیجه با شبکه و سرور تغییر می‌کند؛ جایگزین دادهٔ میدانی Search Console نیست.

اجرای دوبارهٔ خزش:

```sh
python scripts/audit-seo.py https://doctorreson.ir /tmp/doctorreson-seo-live.json
```

## ترتیب انتشار و پذیرش روی دامنهٔ واقعی

ابتدا commit آزموده‌شده به GitHub main فرستاده می‌شود. معیار انتشار، نتیجهٔ `Workers Builds: doctor-resoon1` و پاسخ واقعی `doctorreson.ir` است. Worker جداگانهٔ قدیمی با نام `doctor-resoon` معیار وضعیت دامنهٔ اصلی نیست.

پس از تأیید نسخهٔ دامنهٔ اصلی، همان commit و آرشیو ساخت آزموده‌شده روی پروژهٔ مدیریت‌شدهٔ قبلی منتشر می‌شود. سپس انتقال مسیرهای قدیمی، canonical، sitemap، robots و فایل تأیید از بیرون بررسی می‌شوند. شناسهٔ پروژه، مخاطب عمومی و تنظیم DB مدیریت‌شده حفظ می‌شوند؛ این انتشار انتقال داده بین دو دیتابیس نیست.

## موارد نیازمند حساب مالک

- در Search Console باید property دامنهٔ اصلی `https://doctorreson.ir/` یا Domain property معادل تأیید شود؛ تأیید آدرس قدیمی جای آن را نمی‌گیرد. فایل تأیید روی دامنهٔ اصلی در دسترس است. sitemap نهایی `https://doctorreson.ir/sitemap.xml` است. ثبت sitemap، گزارش‌های خصوصی و Change of Address در این بررسی از داخل حساب گوگل انجام یا تأیید نشده‌اند.
- برای www، در حساب Cloudflare به Worker `doctor-resoon1` یک Custom Domain با نام `www.doctorreson.ir` اضافه شود. کد انتقال آماده است، اما DNS و اتصال دامنه باید در حساب مالک برقرار شوند. دامنهٔ اصلی بدون www برای ایندکس شدن به این مورد وابسته نیست.
- محدودهٔ واقعی خدمات حضوری باید توسط مالک مشخص شود تا اطلاعات محلی دقیق اضافه شود. تا آن زمان، صفحه‌های شهری یا دادهٔ مکانی حدسی ساخته نمی‌شوند.
- ایندکس و رتبه‌بندی تصمیم گوگل است. پس از رفع ایرادها، مشاهدهٔ گزارش Pages و Crawl Stats و درخواست محدود بازخزش در property درست انجام می‌شود. درخواست تکراری، سهمیه را مصرف می‌کند و تضمین تسریع ندارد.
